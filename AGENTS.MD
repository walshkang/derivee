- **Pure Native Swift:** The project has migrated away from React Native / Expo. The app is a pure native iOS application written in Swift (iOS 17.0+).
- **Project Generation:** The Xcode project is generated using `xcodegen`. Do NOT manually modify `.pbxproj` files or configure Xcode through the GUI. Instead, update `project.yml` and run `xcodegen`.
- **Dependencies:** All dependencies (like `H3` and `GRDB`) are managed exclusively via Swift Package Manager (SPM) defined in `project.yml`. Do NOT use CocoaPods or Carthage.
- **Data Layer:** Use `GRDB.swift` for SQLite interactions. Rely on `DatabasePool` with `WAL` mode and standard ROWID tables for **mutable, observed** tables (do NOT use `WITHOUT ROWID` on tables tracked by GRDB `ValueObservation` as it breaks SQLite update hook region tracking — this applies to `explored_hexes` and all tables in the primary database that fire `onChange` callbacks). However, `WITHOUT ROWID` **is permitted** on static, read-only lookup tables in attached databases (e.g. `transit.stop_resolution`) that are never mutated or observed. Use `@Observable` classes with `ValueObservation` for reactive UI updates.
- **Async DB Reads (No Main-Thread Blocking):** All `SpatialDatabaseManager` read methods (`fetchStopDetails`, `fetchHeadwayData`, `isHydrationComplete`, `fetchNeighborhoodName`) **must** use `async`/`await` (`try await dbWriter.read`). **Never** perform synchronous `dbWriter.read { }` on the main thread — this causes priority inversion hangs when the background tracking engine holds a pool connection. The GRDB `Configuration.qos` must be set to `.userInitiated`.
- **Fog Computation Priority:** **All** `SpatialStore.recomputeFogShape()` invocations — both initial and live updates — **must** run at `.userInitiated` priority. **Never** use `.background` priority for fog recomputation; the OS scheduler starves background tasks while the app is in the foreground, causing fog updates to silently never reach the map (hexes appear uncovered only after app restart). The `liveUpdatePriority` init parameter defaults to `.userInitiated`.
- **Fog Startup Synchronization:** On cold start, `recomputeFogShape` and MapLibre's `didFinishLoading` callback race. A "map ready" handshake flag (`isMapStyleLoaded`) in the `MapView.Coordinator` ensures the fog shape is applied as soon as both the style and the shape are ready.
- **Background Tracking:** The background engine relies on `CLLocationUpdate.liveUpdates()` within a detached `Task` and `CLBackgroundActivitySession` to prevent suspension. Do not use legacy `CLLocationManagerDelegate` methods for live updates.
- **Pipeline Diagnostic Logging & Field Testing:** Diagnostic pipeline events must be routed through `PipelineLogger.shared` (`logPipeline(...)`), which mirrors stdout to Apple Unified Logging (`os.Logger`) and persistent on-device storage (`Documents/pipeline_debug.log`). `UIFileSharingEnabled` and `LSSupportsOpeningDocumentsInPlace` are enabled in `project.yml` so logs can be exported directly via the iOS Files app during untethered field testing.
- **Multi-City DB Mounting (Wave L):** Only one city's `transit.sqlite` is attached at a time via `ATTACH DATABASE ... AS transit`. City switching executes `DETACH DATABASE transit` + re-`ATTACH`. All transit queries use the `transit.*` schema prefix and require zero modification per city. Per-city exploration history is stored in `explored_hexes_{slug}` tables within the main database.
- **Multi-City WAL Hot-Swap Safety & `0xdead10cc` Avoidance (Wave L):** The `DETACH`/`ATTACH` transit database swap **must** follow the **Coordinated Two-Phase Barrier** protocol to prevent both `SQLITE_LOCKED` / `SQLITE_BUSY` exceptions and iOS `0xdead10cc` background termination (which kills apps holding open SQLite file locks during suspension):
  1. **Phase 1 — UI Query Teardown (`prepareForCitySwap`):** Cancel/suspend all active foreground transit queries: `TransitRealtimeService` cancels feed polling, `NearbyBusesCapsule` pauses 400m spatial scans, `TransitRevealSheet` auto-dismisses if open.
  2. **Phase 2 — GRDB Serialized Write Barrier:** Execute `dbPool.releaseMemory()` to drain all internal caches and prepared statements across reader connections, then execute `DETACH DATABASE transit` + `ATTACH DATABASE` inside a serial `dbWriter.writeWithoutTransaction { db in ... }` barrier.
  3. **Post-Swap:** Run `PRAGMA transit.optimize;` to warm optimizer stats, then re-enable spatial scans and resume tracking.
  Failure to drain locks via `releaseMemory()` before `DETACH` causes `0xdead10cc` crashes when the app transitions to background with retained file handles.
- **MapLibre Fog Cache Invalidation on City Switch (Wave L):** When switching active cities, assign a **newly initialized** `MLNShapeCollectionFeature` with updated coordinate arrays to `shapeSource.shape` (never mutate existing feature coordinates in-place). Coordinate the camera transition (`mapView.setCenter`) synchronously on `@MainActor` with the shape assignment to prevent intermediate frames rendering a new city's camera over stale fog bounding coordinates.
- **GIS Bridge Preservation in City Pack Compilation (Wave L):** The boolean geographic subtraction for walkable polygon masks must use the formula: `Walkable_Mask = (Neighborhood_Polygon \ Water_Polygons) ∪ Pedestrian_Bridges`. The static GIS compilation script must query OpenStreetMap for pedestrian-accessible bridges (`bridge=yes` with `highway=footway | cycleway | pedestrian | primary/secondary with sidewalk`) and re-add them after water subtraction. Failure to preserve bridge hexes makes $100\%$ neighborhood completion impossible for waterfront neighborhoods.
- **Coordinate-Routed Background Tracking (Wave L):** Live GPS tracking is fully decoupled from the "active view" city. If a user is physically in NYC but browsing Boston stats in Screen 3, newly discovered GPS hexes are always routed to the correct `explored_hexes_{slug}` table based on bounding-box coordinate math. Never insert hexes into the wrong city's table.
- **Zero-Downtime Schema Migration (Wave L):** On first launch with multi-city support, if the legacy `explored_hexes` table exists and `explored_hexes_nyc` does not, execute `ALTER TABLE explored_hexes RENAME TO explored_hexes_nyc;` inside `SpatialDatabaseManager.migrate()`. This preserves 100% of existing user exploration data with zero loss.

## 2. Visual & UI Guidelines
- **SwiftUI Exclusively:** All UI must be built with SwiftUI. No UIKit storyboards or `UIViewController` wrappers unless absolutely necessary for complex MapLibre integrations.
- **Map Focus:** The map is the UI. Avoid heavy persistent HUDs, tab bars, or manual "Start/Stop Tracking" buttons.
- **Aesthetics:** Follow the pure Light Mode guidelines (`.preferredColorScheme(.light)`) with Standard Exploration (`#F9F9F6`) and Transit Navigation (`#FFFFFF`) themes, Electric Amber (`#FFB300`) universal accent, and native frosted glass materials (`.ultraThinMaterial`).
- **2D Top-Down Only (Wave J.1):** 3D terrain tilting and satellite raster layers are prohibited (removed in Wave J.1). The map renders strictly in 2D top-down (`pitch = 0`) with MapTiler Streets v2 vector tiles and flat 2D building footprints via the bundled `composite_style.json`. This ensures 1:1 geographic alignment between the H3 Fog of War polygon mask and the underlying cartography.

## 3. Testing Mandates
- **Split-Target Architecture:**
  - **`DeriveeCoreTests` (No App Host):** Tests core logic (GRDB SQLite transactions, Uber H3 spatial math, multipath GPS noise rejection, multi-threading deadlocks). Runs in milliseconds, completely headlessly without a simulator. Cooperative Task yield testing should be restricted purely to these core database logic tests.
  - **`DeriveeSnapshotTests` (Requires App Host):** Tests SwiftUI layouts (`StatsView`, `TransitRevealSheet`, color accuracy) using `swift-snapshot-testing`. Boots an iPhone simulator in the background on GitHub Actions to prevent visual UI regressions from agent vibe-coding.
- **Data vs Snapshot Assertions:** Use `swift-snapshot-testing` exclusively for SwiftUI visual layers. Keep pure native data assertions (e.g. `interiorPolygons?.count`) for the MapLibre Fog Polygon Math—do not use snapshot/dump diffing for MapLibre structural objects or OpenGL renders.
- **CI/CD Enforcement (Phase 4):** Both test targets run in CI using **GitHub Actions**. Do NOT use Xcode Cloud due to its rigid `.xcodeproj` expectations which conflict with our dynamic `xcodegen` setup. CI acts as a post-push safety net on `main` to catch regressions immediately.
- **Simulator Environment:** The local development environment has advanced to iOS 26.5. When running tests via `xcodebuild`, you MUST explicitly specify a valid simulator destination (e.g., `-destination 'platform=iOS Simulator,name=iPhone 17e,OS=latest'`). Do not use legacy devices like the iPhone 15 Pro.

## 4. Backend & Ecosystem Directives
- **Go Observer Daemon:** Do NOT containerize/Dockerize the Observer daemon. Deploy the raw compiled Go binary directly to the Oracle Cloud ARM instance via `systemd` to avoid virtualized filesystem overhead and maximize SQLite write speeds.
- **Web MVP Brand Sync:** The web app must mirror the iOS aesthetic exactly. Hardcode daytime parchment / white colors (`#F9F9F6` / `#FFFFFF`) in MapLibre, use Electric Amber (`#FFB300`) for sparklines and accents, and pure black/white for text contrast.

## 5. On-Device Routing Engine Directives (Wave N)
- **C++ Interop Architecture:** The RAPTOR routing engine lives in a separate `DeriveeCore` framework target compiled as C++20 (`CLANG_CXX_LANGUAGE_STANDARD: c++20`, `libc++`). Both the framework and app targets require `OTHER_SWIFT_FLAGS: "-cxx-interoperability-mode=default"`. **Zero-bridge protocol:** No JSON serialization, no Objective-C runtime boxing between Swift and C++. Direct C++ type access via Swift interop headers.
- **Timetable Memory Layout:** All timetable structs use `#pragma pack(push, 1)` with 32-bit/16-bit integer offsets (no 64-bit pointers). AoS (Array of Structures) layout only — do NOT use SoA. Struct sizes are locked: `StopTime` (12B), `Trip` (8B), `Route` (12B), `Stop` (20B), `Transfer` (8B).
- **Combined Memory Budget (Critical Guardrail):** The combined on-device routing engine footprint — RAPTOR timetable (~20.64 MB) + ULTRA CSR (~4 MB) + GBFS worker (~1.5 MB) — must stay under **30 MB** (iOS Jetsam ceiling). Current estimate: ~26 MB with ~4 MB headroom. The walk graph runtime footprint is an open design item. **Never** add heap-allocated containers or pointer-chasing data structures inside the C++ hot loop.
- **ULTRA Transfer Shortcuts:** Intermediate transfers (stop-to-stop) are precomputed offline as Pareto-optimal shortcuts and stored in Compressed Sparse Row (CSR) format (`stop_offsets` + `flat_transfers`). **Never** run live Dijkstra or A* during RAPTOR round relaxation — use the CSR flat scan exclusively. Initial/final transfers (user ↔ first/last stop) use bounded one-to-many A* at query time only.
- **GBFS Ephemeral Cache:** Real-time bike-share data lives in a **separate** `gbfs_cache.sqlite` in `NSTemporaryDirectory()` via `DatabaseQueue` (not `DatabasePool`). This is ephemeral data — iOS may purge it under storage pressure. **Never** write GBFS data to the static `transit.sqlite`. All GBFS reads MUST use `async`/`await` per §2.4 mandate. Polling uses `Task`-based async loops (not `Timer.scheduledTimer`) with structured cancellation on sheet dismiss.
- **H3 Index Type Convention:** H3 indices are stored as 15-character hexadecimal TEXT strings at the SQLite layer (e.g., `"8b2a100d213fff"`). In native Swift, C++, and Metal code paths, H3 indices are handled as `UInt64` / `uint64_t` / `H3Index` for GPU buffer storage and bitwise operations. The historical ban on 64-bit integer casting was a JavaScript-era guardrail (IEEE-754 precision loss) and does **not** apply to native code.
- **Routing Query Priority:** All `RoutingEngineBridge.computeJourneys()` invocations run at `.userInitiated` priority via `Task.detached`. Identical to existing fog recomputation pattern. **Never** use `.background` priority for routing queries.
- **120Hz Canvas Rendering Mandate:** The `DepartureMatrixCanvas` (24×60 departure grid) and `ConfidenceBandCanvas` MUST use immediate-mode `Canvas(rendersAsynchronously: true)` + `.drawingGroup()`. **Never** use retained-mode `LazyVGrid`/`ForEach` for high-density grids — these exceed the 8.33ms frame budget. All data must be packed into flat contiguous `[Float]` arrays (4,320 elements for the departure matrix).
- **Circular Time Math:** All GTFS-RT timestamp comparisons crossing midnight MUST use Euclidean modulo arithmetic: `euclideanModulo(a, n) = (a % n + n) % n`. **Never** use raw linear subtraction (`live - scheduled`) for departure delays — this produces 24-hour phantom delays at midnight boundaries. Signed delays are constrained to $[-720, +720]$ minutes.
- **Observer OSM Pipeline (Go):** The Go Observer uses `github.com/qedus/osmpbf` for two-pass PBF extraction. Coordinates are quantized to 32-bit fixed-point (×1e7). All OSM metadata (`Info` struct fields) is stripped. `EdgeFlags uint8` bitmask: bit 0 = Walkable, bit 1 = WheelchairAccessible, bit 2 = IsSteps, bit 3 = IsElevator.
- **View Model Pattern:** All **new** Wave N+ view models MUST use `@Observable` (Swift Observation framework, iOS 17+). **Never** use `@ObservableObject` + `@Published` for new code. Legacy pre-Wave N classes (`AmbientTrackingEngine`) still use `ObservableObject`; migration is tracked separately and must not be mixed into feature work.
