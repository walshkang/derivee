# Agent Operational Rules (Pure Native iOS)

## 1. Core Architecture
- **Reference Documentation:** For visual architecture diagrams (class ownership, the reactive GPS-to-fog pipeline, screen flow state machine, MapLibre layer stack, and database topology), see [docs/diagrams.md](file:///Volumes/T7ssd/derivee/docs/diagrams.md). For prose UI specifications, see [docs/design.md](file:///Volumes/T7ssd/derivee/docs/design.md). For implementation details, see [docs/architecture.md](file:///Volumes/T7ssd/derivee/docs/architecture.md).
- **Pure Native Swift:** The project has migrated away from React Native / Expo. The app is a pure native iOS application written in Swift (iOS 17.0+).
- **Project Generation:** The Xcode project is generated using `xcodegen`. Do NOT manually modify `.pbxproj` files or configure Xcode through the GUI. Instead, update `project.yml` and run `xcodegen`.
- **Dependencies:** All dependencies (like `H3` and `GRDB`) are managed exclusively via Swift Package Manager (SPM) defined in `project.yml`. Do NOT use CocoaPods or Carthage.
- **Data Layer:** Use `GRDB.swift` for SQLite interactions. Rely on `DatabasePool` with `WAL` mode and standard ROWID tables (do NOT use `WITHOUT ROWID` as it breaks GRDB `ValueObservation` SQLite update hook region tracking). Use `@Observable` classes with `ValueObservation` for reactive UI updates.
- **Async DB Reads (No Main-Thread Blocking):** All `SpatialDatabaseManager` read methods (`fetchStopDetails`, `fetchHeadwayData`, `isHydrationComplete`, `fetchNeighborhoodName`) **must** use `async`/`await` (`try await dbWriter.read`). **Never** perform synchronous `dbWriter.read { }` on the main thread — this causes priority inversion hangs when the background tracking engine holds a pool connection. The GRDB `Configuration.qos` must be set to `.userInitiated`.
- **Fog Computation Priority:** **All** `SpatialStore.recomputeFogShape()` invocations — both initial and live updates — **must** run at `.userInitiated` priority. **Never** use `.background` priority for fog recomputation; the OS scheduler starves background tasks while the app is in the foreground, causing fog updates to silently never reach the map (hexes appear uncovered only after app restart). The `liveUpdatePriority` init parameter defaults to `.userInitiated`.
- **Fog Startup Synchronization:** On cold start, `recomputeFogShape` and MapLibre's `didFinishLoading` callback race. A "map ready" handshake flag (`isMapStyleLoaded`) in the `MapView.Coordinator` ensures the fog shape is applied as soon as both the style and the shape are ready.
- **Background Tracking:** The background engine relies on `CLLocationUpdate.liveUpdates()` within a detached `Task` and `CLBackgroundActivitySession` to prevent suspension. Do not use legacy `CLLocationManagerDelegate` methods for live updates.
- **Pipeline Diagnostic Logging & Field Testing:** Diagnostic pipeline events must be routed through `PipelineLogger.shared` (`logPipeline(...)`), which mirrors stdout to Apple Unified Logging (`os.Logger`) and persistent on-device storage (`Documents/pipeline_debug.log`). `UIFileSharingEnabled` and `LSSupportsOpeningDocumentsInPlace` are enabled in `project.yml` so logs can be exported directly via the iOS Files app during untethered field testing.
- **Multi-City DB Mounting (Wave L):** When implemented, only one city's `transit.sqlite` is attached at a time via `ATTACH DATABASE ... AS transit`. City switching executes `DETACH DATABASE transit` + re-`ATTACH`. All transit queries use the `transit.*` schema prefix and require zero modification per city. Per-city exploration history is stored in `explored_hexes_{slug}` tables within the main database.

## 2. Visual & UI Guidelines
- **SwiftUI Exclusively:** All UI must be built with SwiftUI. No UIKit storyboards or `UIViewController` wrappers unless absolutely necessary for complex MapLibre integrations.
- **Map Focus:** The map is the UI. Avoid heavy persistent HUDs, tab bars, or manual "Start/Stop Tracking" buttons.
- **Aesthetics:** Follow the pure Light Mode guidelines (`.preferredColorScheme(.light)`) with Standard Exploration (`#F9F9F6`) and Transit Navigation (`#FFFFFF`) themes, Electric Amber (`#FFB300`) universal accent, and native frosted glass materials (`.ultraThinMaterial`).

## 3. Testing Mandates
- **Split-Target Architecture:**
  - **`DeriveeCoreTests` (No App Host):** Tests core logic (GRDB SQLite transactions, Uber H3 spatial math, multipath GPS noise rejection, multi-threading deadlocks). Runs in milliseconds, completely headlessly without a simulator. Cooperative Task yield testing should be restricted purely to these core database logic tests.
  - **`DeriveeSnapshotTests` (Requires App Host):** Tests SwiftUI layouts (`StatsView`, `TransitRevealSheet`, color accuracy) using `swift-snapshot-testing`. Boots an iPhone simulator in the background on GitHub Actions to prevent visual UI regressions from agent vibe-coding.
- **Data vs Snapshot Assertions:** Use `swift-snapshot-testing` exclusively for SwiftUI visual layers. Keep pure native data assertions (e.g. `interiorPolygons?.count`) for the MapLibre Fog Polygon Math—do not use snapshot/dump diffing for MapLibre structural objects or OpenGL renders.
- **CI/CD Enforcement (Phase 4):** Both test targets run in CI using **GitHub Actions**. Do NOT use Xcode Cloud due to its rigid `.xcodeproj` expectations which conflict with our dynamic `xcodegen` setup. CI acts as a post-push safety net on `main` to catch regressions immediately.
- **Simulator Environment:** The local development environment has advanced to iOS 26.5. When running tests via `xcodebuild`, you MUST explicitly specify a valid simulator destination (e.g., `-destination 'platform=iOS Simulator,name=iPhone 17e,OS=latest'`). Do not use legacy devices like the iPhone 15 Pro.

## 4. Backend & Ecosystem Directives
- **Go Observer Daemon:** Do NOT containerize/Dockerize the Observer daemon. Deploy the raw compiled Go binary directly to the Oracle Cloud ARM instance via `systemd` to avoid virtualized filesystem overhead and maximize SQLite write speeds.
- **Web MVP Brand Sync:** The web app must mirror the iOS aesthetic exactly. Hardcode daytime parchment / white colors (`#F9F9F6` / `#FFFFFF`) in MapLibre, use Electric Amber (`#FFB300`) for sparklines and accents, and pure black/white for text contrast.
